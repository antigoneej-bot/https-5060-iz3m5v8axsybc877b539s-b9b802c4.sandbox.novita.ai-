# 마음냥 정원 1.0.22+25 — 간직한 마음을 다시 만나는 흐름

기준 소스는 1.0.21+24입니다. 이 버전은 답장 대신 도입했던 편지 마무리·돌봄·기록집을 실제 정원의 기억과 연결합니다. 기존 카카오 로그인, Firebase 설정, Play Integrity, 결제 상품과 구매 검증은 바꾸지 않습니다.

## 화면에서 달라진 부분

| 어디에서 | 새로 할 수 있는 일 |
| --- | --- |
| 편지를 저장한 뒤 | 원문에서 고른 문장을 내 정원에 심은 식물의 기억으로 연결합니다. 긴 문장은 직접 짧은 부분을 골라 남깁니다. |
| 나를 돌보는 방법 → 간직한 말 다시 보기 | 내 문장·나에게 남긴 말·받은 응원을 골라 봅니다. 원래 편지를 열거나 문장을 내 나무에 연결할 수 있습니다. |
| 나를 돌보는 방법 → 도움이 됐던 돌봄 꺼내기 | 본인이 도움이 됐다고 표시한 최근 경험을 다시 꺼내 새 계획을 남깁니다. 과거 상황도 확인하고 바꿀 수 있습니다. |
| 내 식물의 기억 | 편지 날짜와 선택한 문장을 다시 보고 원래 편지와 해당 달의 기록집으로 이동합니다. 일반 편지와 마음 편지를 모두 연결합니다. |
| 냥이 마을 → 함께 가꾸는 기념 나무 | 실제 초대·물주기·메모 등의 새 활동 표시와 최근 활동을 확인합니다. |
| 공동 나무 → 내가 남긴 공동 메모 관리 | 이웃 연결 종료·차단 뒤에도 본인이 쓴 메모를 확인하고 삭제합니다. 상대의 기록은 이 경로로 보이지 않습니다. |
| 정원 소식 → 내 신청 내역 | 신청한 모임의 날짜·회차·상태를 보고 취소하거나 해당 공지를 엽니다. |

개인 편지와 식물의 추억은 공개 정원이나 공동 나무로 자동 전송되지 않습니다. 말과 돌봄을 열람하거나 명상 화면에 다녀온 것만으로 실천 완료·도움 여부를 자동 기록하지 않습니다. 새 활동 표시는 화면 진입·새로고침·앱 복귀 때 갱신하며 휴대전화 푸시 알림은 아닙니다.

## 함께 수정한 오류

- 편지·돌봄·식물 기억 삭제에서 저장 오류가 발생하면 같은 작업에서 제거한 연결 기록도 복구합니다. 복구 자체가 실패한 경우 성공으로 표시하지 않습니다.
- 백업과 연결 기록 변경을 같은 순서로 처리하여 삭제 전 문장 복사본과 삭제 후 원본 목록이 뒤섞인 백업을 만들지 않도록 했습니다.
- UTC로 저장된 기록도 기기의 현지 날짜를 기준으로 주간·월간 통계를 계산합니다.
- 첫 무료 기본 기록집을 지웠다가 다른 달에 다시 만드는 경우 무료 생성 여부가 초기화되지 않도록 했습니다. 기존 기록집의 열람·편집은 유지합니다.
- 이웃 연결을 다시 맺어도 예전 공동 나무의 참여 권한이 자동 재개되지 않습니다. 새 초대와 수락이 필요합니다.
- 공동 나무 나가기·초대 거절 후 통신 응답이 유실되어 재시도해도 이미 완료된 결과를 유지합니다.
- 예약 확정 응답을 즉시 반영하여 후속 조회 실패를 예약 실패로 표시하지 않습니다.
- 신청자가 있는 기존 모임의 정원 삭제·과도한 축소를 막고, 기존 신청 취소 경로를 유지합니다.
- 공지 삭제 중 문제가 생기면 운영자에게 ‘삭제 마무리하기’를 제공하여 이어서 처리할 수 있습니다.

## 적용과 확인

1. 현재 프로젝트를 보관하고 업데이트 ZIP의 `apply_update.py --project 프로젝트경로 --check`를 실행합니다. 이 업데이트는 1.0.21+24 기준입니다. 다른 수정이 있으면 자동 덮어쓰지 않고 충돌 파일을 표시합니다.
2. 검사가 통과하면 같은 명령의 `--check`를 `--apply`로 바꾸어 적용합니다. 변경 전 파일을 별도로 보관합니다. 전체 소스 ZIP에도 이전 기능과 이번 수정이 모두 들어 있습니다.
3. 기존 운영 환경을 유지하여 `gardenApi`의 공지·공동 나무 변경을 배포합니다. 로그인 서버·구독 알림 서버·서비스 계정·서명키를 새로 만들 필요는 없습니다.
4. 기존 서명키가 있는 환경에서 `bash tool/build_mindnyang_play_bundle.sh`로 빌드하고 Play 내부 테스트 트랙에 올립니다. 이 소스의 버전 코드는 25이며 이미 그 이상을 사용했다면 더 높여야 합니다.
5. Play에서 업데이트한 실제 계정 두 개로 초대 → 수락 → 물주기·메모 → 새 활동 확인을 테스트합니다. 카카오 로그인 유지와 구독 복원, 모임 신청·취소도 함께 확인합니다.

이번 결과물은 수정 소스입니다. 운영 서버 배포·Play 업로드·서명된 APK/AAB 생성·실제 두 휴대전화 검증을 완료했다고 표시하지 않습니다. 저장 실패 복구는 앱 실행 중의 저장 오류를 다루며, 여러 저장 파일에 걸친 강제 종료나 디스크 고장의 완전한 복구까지 보장하지 않습니다.

정확한 로컬 검증 결과는 `RELEASE_VERIFICATION.md`에 기록합니다.
