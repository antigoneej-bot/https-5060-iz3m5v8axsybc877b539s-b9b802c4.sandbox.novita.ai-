# 기념 나무와 날짜별 추억

## 사용자 흐름

1. 나의 정원 → 추억 → 심어 둔 식물을 선택합니다. 정원 장면의 식물을 눌러도 같은 편집기가 열립니다.
2. 식물의 이름과 함께 기억할 시작일을 고릅니다. 시작일 지정은 선택 사항이며, 실제 심은 날과 별도로 표시됩니다.
3. 날짜를 골라 짧은 추억을 추가합니다. 식물별 최대 60개, 각 300자까지 보관하며 이전 추억을 수정하거나 삭제할 수 있습니다.
4. 저장을 눌러 반영합니다. 취소하면 이름·날짜·추억의 편집은 반영되지 않습니다. 물주기는 기존대로 즉시 저장됩니다.
5. 선택한 시작일을 1일째로 계산합니다. 추억 도구에서 경과일을 확인하고, 30일·100일 이후 해당 기념 엽서를 언제든 만들 수 있습니다. 매일 접속해야 하는 조건은 없습니다.
6. 기념 엽서 버튼은 식물 이름과 선택한 기념일 수만 문장에 넣습니다. 본문을 넣고 싶으면 엽서 화면의 '식물의 추억에서 직접 고르기'에서 날짜별 기록을 고릅니다. 공유 전에 문장을 고칠 수 있습니다.

## 데이터·개인정보

- 기존 `garden_memories_local_user` 암호화 상자를 그대로 사용합니다. 식물 종류별 한 기록 구조는 유지합니다.
- 버전 2는 `anniversaryOn`(달력 날짜)와 `entries`(ID·날짜·본문)를 추가합니다. 기존 `note` 필드는 마지막 추억을 유지해 이전 읽기 경로와 호환합니다.
- 기존 단일 추억은 기존 저장일의 한 기록으로 표시합니다. 실제 기념 시작일은 임의로 생성하지 않습니다.
- 60개를 넘는 입력은 거절하며 오래된 추억을 자동 삭제하지 않습니다. ID 중복, 잘못된 날짜, 지원하지 않는 버전과 불일치한 마지막 본문도 검증합니다.
- 기존 백업 허용 상자 및 `PlantMemory.fromJson` 검증을 이용하므로 전체 추억과 기념일도 암호화 백업에 포함됩니다. 새 저장소 복원에서 보존을 검증했습니다. 이미 같은 식물 기록이 있으면 기존 백업 정책대로 현재 기록을 유지하며 타임라인 자동 병합은 하지 않습니다.
- 식물 이름·기념일·추억은 공개 정원 DTO에 추가하지 않습니다. 기념 카드에서 엽서를 여는 행동과 공유 버튼을 누르는 행동을 구분합니다.
- 날짜 계산은 달력 날짜 기준으로 처리해 시간대·일광절약시간의 시간 차이를 성장일 수에 적용하지 않습니다.

## 범위

기념일은 앱 내 카드이며 푸시 알림 예약은 아닙니다. 두 사람이 같은 나무를 동시에 편집하는 공동 소유 기능은 아닙니다. 기념 경과일은 감정 수치나 식물 물주기 성장량을 바꾸지 않습니다.

## 검증

`test/plant_anniversary_test.dart`는 기존 단일 추억 전환, 윤년·미래 날짜·30/100일 경계, 잘못된 데이터 거절, 실제 암호화 백업/빈 저장소 복원, 360px 기념 카드·엽서 연결, 360px 추억 편집 취소 보존을 검증합니다. 기존 정원 성장과 고양이 이름 엽서 테스트도 함께 실행합니다.
