# 마음냥 정원 연결 보완 — 1.0.15+18

기준: 2026-10-16 전달한 전체 검토판 1.0.14+17. 이번에는 개인 회고와 정원·이웃 사이의 실제 연결을 보완했습니다.

## 달라진 사용 흐름

| 기능 | 사용 경로와 동작 |
|---|---|
| 통합 감정 통계 | 마음 리포트·감정 통계에서 편지와 정원 일기를 함께 집계합니다. 날짜를 누르면 출처별 기록을 확인합니다. |
| 통계 숫자 해석 | 입력된 일기의 감정 강도 1~5만 평균에 사용합니다. 편지에 없는 강도를 만들거나 돌봄 보상 온기를 감정 점수로 사용하지 않습니다. |
| 명상 후 돌아보기 | 주간 돌아보기·명상 목록의 ‘이번 주 나를 도운 것’에서 최근 7일의 본인 응답과 다음 행동을 확인합니다. 편안했던 명상 열기 또는 불편할 때 잠시 쉬기가 연결됩니다. 자동 재생하지 않습니다. |
| 기념 나무 | 심은 식물을 눌러 이름·선택 기념일·날짜별 추억을 남깁니다. 식물마다 최대 60개입니다. 정원 기록·활동의 추억 영역에서 30일·100일 기념 엽서를 만들 수 있습니다. |
| 정원 소식 | 넓은 정원 상단 ‘정원 소식’에서 지난 방문 이후 실제 기록·식물 변화, 받은 마음, 공개 정원 업데이트를 확인합니다. 미확인 마음은 작은 점으로 표시합니다. |
| 공개 모습 업데이트 | 공개 설정에 마지막 저장 시각과 반영되지 않은 변화가 표시됩니다. ‘지금 정원 모습 업데이트’는 서버의 현재 공개 범위·이름·선물 수신 설정을 유지합니다. |
| 오래된 받은 마음 | 받은 마음의 더 불러오기와 보관한 꽃 선물 선택창의 더 불러오기로 오래된 항목까지 조회합니다. 페이지 오류가 나도 이미 받은 목록은 유지합니다. |
| 공개 정원 탐색 | 둘러보기가 첫 80개 후보에 고정되지 않고 다음 페이지로 이어집니다. 차단·비공개 정원은 모든 페이지에서 제외합니다. |

## 개인정보와 저장

기념일과 추억 본문은 기존 암호화 저장소와 백업에 포함됩니다. 공개 정원에 자동 포함하지 않습니다. 엽서 내용은 사용자가 확인·선택한 뒤 공유합니다. 기존 단일 추억은 날짜별 첫 기록으로 이어지며, 기존 백업 복원은 현재 기록 우선 정책을 유지합니다.

정원 소식의 읽음·방문 표시는 이 기기의 계정별 보조 정보이며 서버 수령 처리나 재화를 변경하지 않습니다. 계정이 바뀌면 열린 소식 시트의 이전 계정 요약도 숨깁니다. 배지는 앱에서 조회한 항목 기준이며 모든 기기의 읽음 상태를 동기화하는 기능이나 푸시 알림은 아닙니다. 앱을 닫은 동안의 성장을 만들어내지 않습니다.

이번 기념 나무는 개인 정원의 식물별 기록입니다. 두 사람이 하나의 나무를 공동 편집하는 기능이나 기념일 푸시는 추가하지 않았습니다. 명상 응답은 본인이 남긴 기록이며 치료 효과나 정신건강 진단 결과가 아닙니다.

## 적용·배포 순서

1. 기존 프로젝트·서명키·배포 설정을 보존하고 패치를 프로젝트 밖에 풉니다. 아래 기본 명령은 검사만 합니다.

   ```sh
   python3 apply_improvements_patch.py --project /home/user/flutter_app
   ```

2. 충돌이 없으면 같은 명령에 `--apply`를 붙여 적용합니다. 기준 파일에 별도 수정이 있으면 자동 적용은 중단하며 파일을 덮어쓰지 않습니다. 이때 별도 수정과 패치를 병합하세요. 이미 적용한 파일은 건너뜁니다.

   ```sh
   python3 apply_improvements_patch.py --project /home/user/flutter_app --apply
   ```

3. **이번에는 Firebase Functions 서버 재배포가 필요합니다.** 기존 운영 프로젝트가 선택됐는지 확인하고 프로젝트 루트에서 실행합니다.

   ```sh
   firebase deploy --only functions:gardenApi
   ```

   새 비밀키·새 복합 색인은 추가하지 않았습니다. 이전 냥이 마을 배포에 포함됐던 색인과 인증·App Check 설정은 계속 필요합니다. 이전 배포를 생략했다면 `docs/GARDEN_VILLAGE_RELEASE.md`의 해당 설정을 먼저 적용하세요. 접근 규칙이나 App Check를 해제하지 마세요. 기존 서버에서는 새 페이지가 제공되지 않고 모습만 업데이트 기능은 비활성화될 수 있습니다.

4. 기존 Flutter 환경에서 `flutter pub get`, `flutter analyze`, `flutter test` 후 기존 서버 URL과 로그인·서명 설정으로 새 APK/AAB를 만듭니다. 이 소스 버전은 **1.0.15+18**입니다. Play에 이미 18 이상을 올렸다면 사용한 값보다 높은 build number로 바꿉니다.
5. 테스트 트랙에 새 빌드를 배포하고 두 실제 계정·기기로 아래 항목을 확인합니다. 기존 APK는 소스 변경만으로 갱신되지 않습니다.

## 두 기기 최종 확인

- A에서 정원 배치 변경 → 미반영 안내 → 업데이트 → B가 다시 방문해 새 배치 확인.
- A의 다른 기기에서 비공개로 변경한 뒤 기존 화면에서 모습만 업데이트해도 비공개 유지.
- B의 응원·꽃이 A의 받은 마음에 도착하고 정원 소식에 확인 표시가 나타나는지 확인.
- 여러 페이지의 받은 꽃·공개 정원을 조회하고, 오래된 미심기 꽃을 선물할 수 있는지 확인.
- 꽃을 심거나 옮긴 뒤 다른 기기에서도 중복 심기·전송이 거부되는지 확인.
- 소식/받은 마음 화면을 연 상태에서 로그아웃·다른 계정 로그인 시 이전 요약·목록이 사라지는지 확인.
- 기념일·추억 저장 → 앱 재시작 → 백업·복원 후 유지 여부 확인.
- 편지와 정원 일기 각각 작성 → 주간/월간 숫자와 날짜 상세 확인, 명상 후 응답 → 회고 카드 반영 확인.

## 검증 범위와 남은 운영 작업

자동 검증 결과는 `GARDEN_CONNECTIONS_VERIFICATION.json`과 패치의 `verification/`에 있습니다. 실제 Firebase 배포·두 기기 통신·서명 APK/AAB 생성·Play 제출은 이 작업 환경에서 수행하지 않았습니다. 웹 빌드 성공은 Android 운영 로그인·결제 성공을 뜻하지 않습니다.

서버에서 이미 옮긴 선물의 ID 목록은 다른 기기에서 되살아나는 것을 막기 위해 기존 방식으로 함께 조회합니다. 이 보조 목록은 전송 누적량에 따라 증가하므로, 규모가 커지면 별도 동기화 커서로 전환해야 합니다. 자세한 서버 계약은 `backend/village-api.md`를 참고하세요.
