91번 개선 작업
기준: 1.0.87+90, 5cb4dba. 이전 작업본과 APK/AAB/ZIP은 보존.

1. 이웃: getVillageEntry 통합 API를 추가. 기존 인증/계정 잠금 안에서 프로필+목록 반환.
   기존 서버가 unknown-action을 명시할 때만 순차 요청으로 호환. 계정 변경·권한 실패·시간초과는 추가 요청으로 우회하지 않음.
   이웃 카드 조회는 최대 4개 동시 처리, 기존 공개/차단/삭제 검증과 결과 순서 유지.
   인증/App Check 단계 각각 15초, HTTP 50초 제한. 쓰기 작업의 시간초과를 자동 재전송하지 않음.
   실제 운영 속도는 서버 배포와 실기기 단계별 측정 전에는 미검증.

2. 오류 수집: 현재 firebase_core 3.6.0과 호환되는 firebase_crashlytics 4.1.3 추가.
   Google Maven에서 확인한 Crashlytics Gradle 플러그인 3.0.8 사용.
   별도 오류 공유 설정, 기본 꺼짐. Flutter/비동기 오류는 원문 대신 오류 종류, 호출 스택, 허용된 단계명만 기록.
   UID/이메일/토큰/편지/감정 원문을 직접 첨부하지 않음. 네이티브 진단에는 SDK의 기기/설치 진단 정보가 포함될 수 있음.
   설정 전 쌓인 대기 보고서는 삭제 후 수집 켜기. 사용 통계 동의와 분리.
   실제 Firebase 수신 확인 및 테스트 크래시는 미검증. 사용자 기록이 있는 폰에서 강제 크래시를 실행하지 않음.
   로컬 빌드에서 심볼/매핑 자동 업로드는 끔. 검토 후 -PuploadCrashlyticsSymbols=true로 운영자가 명시적으로 업로드 가능.

3. 백업: 상태 코드와 마지막 성공 시각을 분리. 암호화/업로드/실패 상태와 원인별 조치 제공.
   실패해도 성공 시각/다이제스트를 성공처럼 갱신하지 않고, 계정 변경 시 이전 계정 진행 표시 제거.
   저장소·백업 암호화 포맷·구독 권한·개인 기록 유지. 화면의 백업 상태는 언어 변경 시 다시 번역.

4. 문구: 복원 중/실패 화면 영어화, 언어 설정을 기록 로딩 전에 읽어 초기 복구 화면에도 반영.
   실제 첫 인사 보상과 준비 중인 추가 통합을 구분. 가격·상품 ID·보상 수치 변경 없음.

5. 반복 검증: .github/workflows/quality.yml 추가. 고정 Flutter 3.35.4, Node22,
   잠금 파일·분석·전체 Flutter/서버 테스트·출시 설정 검사. 배포/업로드/서명 비밀값 없음.
   로컬 저장소 루트가 flutter_app인 구조 기준. 상위 래퍼 저장소에 넣을 경우 workflow 위치/작업 디렉터리를 먼저 맞출 것.
   GitHub 원격에 아직 올리지 않았으며 실제 CI 실행은 미검증.
