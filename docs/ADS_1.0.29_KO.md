# 마음냥 정원 1.0.29+32 — Android 홈 배너 광고 연결 준비

기준: 1.0.28+31. 기억의 나무/심은 나무 관리 수정과 기존 로그인·결제·정원 기능을 보존합니다.

## 반영한 동작

- 무료 이용자에게 홈 내용 아래 배너 한 곳만 표시합니다. 홈을 스크롤하면 볼 수 있으며 하단 내비게이션 위에 겹쳐 띄우지 않습니다.
- 편지 작성, 명상, 정원, 로그인, 구독 결제, 상담 도움 찾기 화면에는 광고를 넣지 않습니다. 전면/앱 시작/보상형 광고는 활성화하지 않았습니다.
- 구독·구독 무료체험 중에는 광고를 요청하지 않습니다. 로그인 계정의 구독 확인이 미완료·오래됨·실패인 경우도 광고를 숨깁니다. 로그아웃 상태는 무료 이용으로 취급합니다.
- 구매/계정/동의 변경, 다른 화면 이동, 백그라운드 전환 시 기존 광고를 제거합니다. 이전 로딩 결과는 재표시하지 않습니다.
- 360/390px 등에서 사용 가능한 폭에 맞는 배너를 요청합니다. 실패하거나 표시할 광고가 없으면 빈칸 없이 접힙니다. 앱 콘텐츠는 그대로 이용할 수 있습니다.
- 광고가 연결된 빌드의 마이에 ‘광고 개인정보 선택’을 추가하고 구독 혜택에 광고 없는 이용을 표시합니다.
- Google UMP 동의 정보 갱신과 필요한 폼 표시를 먼저 처리합니다. 늦은 응답으로 편지/명상 화면 위에 동의 창을 새로 열지 않습니다.
- 비맞춤 광고 요청, SDK 앱 음소거, PG 콘텐츠 등급 제한을 적용합니다. 이 설정이 모든 광고 내용의 적합성을 보증하는 것은 아닙니다. 운영 시 AdMob 차단 관리도 검토합니다.
- 편지·감정·마음 점수·친구 코드·로그인 계정은 광고 요청 필드에 넣지 않습니다. SDK 자체의 기기 정보·IP·광고 상호작용 등 처리는 앱 안내에 명시합니다.

## 아직 실제 광고가 송출되는 상태는 아닙니다

현재 사용자의 AdMob 앱 ID와 배너 광고 단위 ID가 없으므로 수익 광고는 비활성입니다. ID가 없는 릴리스 빌드에서는 테스트 광고로 몰래 대체하지 않습니다. 실제 광고 수신/노출, 수익 집계, 실기기 SDK 확인은 완료하지 않았습니다.

1. https://admob.google.com/ 에서 Android 앱을 등록합니다. 패키지는 기존 `com.mysticcat.journal`입니다. Firebase 앱 ID, OAuth 클라이언트 ID와는 다른 값입니다.
2. AdMob 앱 ID (`ca-app-pub-숫자~숫자`)와 배너 광고 단위 ID (`ca-app-pub-숫자/숫자`)를 발급받습니다. 둘 다 같은 게시자 계정이어야 합니다. 비밀번호·로그인 토큰·결제 비밀키는 필요 없습니다.
3. AdMob의 개인정보 보호 및 메시지 설정을 준비하고, 개발자 웹사이트의 app-ads.txt로 앱을 확인합니다. 공식 문서상 앱 확인 및 준비 상태 검토를 거쳐야 광고가 완전히 송출됩니다. 내부 테스트 등록만으로 이 검토가 완료됐다고 보아서는 안 됩니다.
4. 공개 개인정보처리방침에 앱 내 광고 안내와 같은 내용을 반영하고 Play Console의 광고 포함/데이터 보안/광고 ID 사용 응답을 실제 SDK 및 설정에 맞게 업데이트합니다. 이 문서가 모든 개인정보 고지를 대신하지는 않습니다.
5. 아래 방식으로 새 AAB를 만든 뒤 같은 Play 앱에 업데이트합니다. 이번 앱 코드 변경을 위해 로그인/결제/정원 서버를 재배포할 필요는 없습니다.

## 빌드

기존 서명키, Firebase 설정, 배포 주소를 그대로 사용합니다. 아래 환경변수에 발급받은 두 공개 ID를 넣고 `bash tool/build_mindnyang_play_bundle.sh`를 실행합니다.

```
export ADMOB_ANDROID_APP_ID='발급받은 앱 ID'
export ADMOB_ANDROID_BANNER_ID='발급받은 배너 광고 단위 ID'
bash tool/build_mindnyang_play_bundle.sh
```

공통 빌드 도구가 ID 형식과 게시자 일치를 확인하고 Dart 빌드 값과 Android manifest에 같은 앱 ID를 전달합니다. 수동 Flutter 빌드 시에도 두 `--dart-define=ADMOB_ANDROID_APP_ID=...` 및 `--dart-define=ADMOB_ANDROID_BANNER_ID=...`를 함께 사용합니다. 예전의 별도 Gradle `ADMOB_APP_ID` 설정 대신 이 두 값을 사용합니다.

테스트 전용으로는 `ADMOB_TEST_ADS=true bash tool/build_mindnyang_play_bundle.sh`를 사용할 수 있습니다. 이 경우 Google 공식 테스트 ID만 사용하며 광고 수익은 발생하지 않습니다. 정식 배포에는 테스트 모드를 빼고 실제 ID를 적용합니다. 디버그 빌드는 실제 ID를 넣더라도 Google 테스트 광고만 요청합니다. 앱 ID만 바꾸어 버전 31 AAB에 광고를 붙일 수는 없으며 새 빌드가 필요합니다.

이번 전달본은 소스 수정본입니다. 새 APK/AAB 제작·Play 업로드·AdMob 설정 변경·실기기 노출 검증을 수행했다고 주장하지 않습니다. Google Mobile Ads Flutter 5.3.1 및 기존 종속성은 변경하지 않았습니다.

## 검증 범위

전체 Flutter 테스트 597개, 서버 연결 설정을 켠 광고·구독 캐시 테스트 39개, 빌드 설정 검사 8개가 통과했습니다. 정적 분석 오류는 0개입니다. Android 릴리스 manifest 처리도 통과하여 테스트 앱 ID와 SDK 측정 지연 설정을 확인했습니다. 이는 실제 광고 수신 확인이나 새 AAB 제작을 뜻하지 않습니다.

테스트 광고 서버를 호출하지 않는 위젯/단위 테스트로 화면 폭·숨김·실패·구독 전환·계정 경합·생명주기·UMP 호출 순서를 확인합니다. 앱의 실제 SDK와 AdMob 계정 연결은 ID 설정 후 별도 실기기 확인이 필요합니다.

- 무료 계정: 홈 하단에서 배너, 편지·정원·명상에서는 배너 없음.
- 구독 계정 및 무료체험 계정: 배너 없음.
- 광고를 로딩하는 중 구매/로그아웃/계정 변경: 이전 광고가 재등장하지 않음.
- 광고 요청 실패/인터넷 끊김: 홈의 버튼과 기록 기능이 계속 작동.
- 동의 선택 변경 후 기존 광고 해제 및 새 조건 반영.
