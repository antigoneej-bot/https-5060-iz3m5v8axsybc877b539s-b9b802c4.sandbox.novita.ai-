# 배경음악 시작 수정 · 1.0.34+37

## 확인한 원인

기존 홈 진입부는 GestureDetector의 onTap에서만 tryStartBgm을 호출했습니다. 배경음악을 ON으로 저장해도 앱 실행 직후 자동 재생 요청이 없었고, 자식 버튼이 탭을 처리하면 상위의 onTap이 실행되지 않는 경우도 있었습니다. 음악을 멈췄던 명상/영상 종료 후에도 배경음악 재개 요청이 없었습니다.

bgm_mystic.mp3의 처음 8초를 검사했으며, -50dB 기준 0.3초 이상 지속되는 무음은 감지되지 않았습니다. 음악 원본 파일은 수정하지 않았습니다.

## 변경

- 휴대전화 앱의 첫 화면이 표시되면 저장된 음악 ON/OFF와 볼륨에 따라 자동 시작합니다.
- 앱을 처음 준비할 때 내장 음원을 미리 불러옵니다. 음원 준비 실패나 지연이 기록 화면 진입을 막지 않도록 비동기로 처리합니다.
- 화면을 여러 번 눌러도 음악을 중복 실행하거나 처음부터 다시 시작하지 않습니다.
- 앱이 배경으로 이동하거나 앱 잠금 화면이 표시되면 BGM을 일시정지합니다. 다시 사용 가능한 화면으로 돌아오면 이어서 재생합니다.
- 명상/영상이 소리를 사용 중이면 BGM을 재생하지 않습니다. 해당 재생이 종료되거나 일시정지되어 소리 사용이 해제되면, 화면이 열려 있고 음악이 ON일 때만 BGM을 재개합니다.
- 명상 오디오의 기존 화면 잠금/배경 재생 기능은 유지합니다. 새 화면 제어는 BGM에만 적용됩니다.
- 사용자가 음악을 OFF로 설정했거나 앱의 종료 버튼으로 정원을 닫은 상태에서는 자동 재생하지 않습니다. 정원 다시 열기는 명시적으로 재생을 재개합니다.
- 웹에서는 브라우저의 자동 재생 제한을 고려해 첫 터치로 시작할 수 있도록 유지합니다. 버튼 터치도 감지하며 버튼 자체의 동작을 가로채지 않습니다.
- 음악 파일, 로그인, 결제, 서버 설정 및 서명키는 변경하지 않습니다.

## 검증 범위

새 테스트는 자동 시작, 저장된 OFF, 볼륨·반복 재생, 중복 터치, 앱 복귀, 로딩 도중 OFF/배경 전환, 일시적 음원 오류의 재시도, 명상 소리 우선권, 화면 이동 및 실제 AppLockGate 잠금/해제를 검증합니다. 오디오 플랫폼은 테스트 대역을 사용하므로 실제 휴대전화의 소리와 시작 지연 시간은 업데이트 후 확인해야 합니다.

Play 내부 테스트에 버전 37 AAB를 올리고 기존 앱을 업데이트합니다. 서버 배포 및 토큰 재등록은 필요하지 않습니다. 휴대전화 미디어 볼륨과 앱의 배경음악 ON을 확인한 뒤 앱을 완전히 닫았다가 다시 열어, 화면을 터치하지 않아도 음악이 시작되는지 확인하세요. 잠금을 사용 중이면 잠금 해제 후 시작해야 합니다.
