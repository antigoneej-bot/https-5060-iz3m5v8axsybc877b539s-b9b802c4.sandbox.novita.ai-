# 마음냥 정원 1.0.27+30 — 전체 소스 검토 후 보완

이 버전은 1.0.26+29의 빛의 정수 표시, 월간·연간 상품 선택/구독 관리, 물·거름·햇볕 성장 기능을 모두 포함합니다. 설치된 앱이나 운영 서버에 자동 적용된 것은 아닙니다.

## 수정 내용

1. **명상 후 감정 기록 암호화**
   - 명상 후 '편안해짐/비슷함/불편함' 응답과 날짜를 암호화된 Hive 저장소에 보관합니다.
   - 기존 일반 설정에 있는 기록은 복사·저장 확인 후 제거합니다. 이전 암호화 Hive 형식도 읽습니다.
   - 저장 실패 시 원본을 보존하며 평문 저장으로 우회하지 않습니다. 손상된 원본도 함부로 덮어쓰지 않습니다.
   - 백업의 기존 `meditation.checkins` 항목을 유지하되, 복원할 때에는 암호화 저장소로 바로 넣습니다. 기존 기기의 응답을 우선하고 같은 세션은 중복하지 않습니다.

2. **아침·저녁 알림의 저장 결과 반영**
   - 휴대전화에 알림 예약이 성공한 후에만 켜짐과 시간을 저장합니다.
   - 예약, 시간 변경, 취소 실패는 화면에 알리고 가능한 경우 이전 설정을 유지합니다. 연속 탭도 순서대로 처리합니다.
   - 방문·스트릭 알림의 기존 기능은 유지합니다. 이 기능은 로컬 알림이며 이웃 선물이나 공지의 서버 푸시를 추가한 것은 아닙니다.

3. **공지 저장 중 연결이 끊겨도 중복 생성 방지**
   - 앱은 공개 저장 전에 작성 내용과 고유 요청 번호를 암호화 임시저장합니다.
   - 서버는 운영자와 요청 번호를 기준으로 같은 저장 요청을 한 번만 처리합니다. 내용이 바뀐 요청 번호의 오용은 거부합니다.
   - 응답을 못 받은 뒤 화면을 닫았다 열어도 처음 요청을 확인합니다. 그 사이 고친 내용은 같은 공지를 수정합니다.
   - 삭제한 글은 늦게 도착한 재시도로 다시 생기지 않습니다. 운영자 권한·예약 정원 검사는 유지됩니다.
   - **이 기능은 새 앱과 gardenApi 서버 수정본이 함께 적용되어야 합니다.** 구버전 앱의 작성 요청은 기존 방식으로 계속 받습니다.

4. **명상 완료 기록의 재시작 복구**
   - 코스 진행과 하루 명상 보상을 하나의 암호화된 처리 대기 기록에 먼저 남깁니다.
   - 일부 처리 후 실패하더라도 다음 실행/재생/재시도에서 이어 처리하며 코스 진행과 보상을 중복하지 않습니다.
   - 기기 저장 자체가 실패하면 앱을 닫기 전에 재시도하라는 안내를 표시합니다. 기기 저장 공간 자체가 전혀 작동하지 않는 경우까지 보존을 보장하지 않습니다.
   - 처리 대기 기록은 해당 기기의 복구용이며 다른 기기로 가져가는 백업에는 포함하지 않습니다.

5. **성장한 나무의 화면 경계와 배치**
   - 처음부터 다 자란 나무의 폭을 기준으로 가장자리 여유를 확보합니다. 새 나무가 자라며 뿌리가 옆으로 움직이지 않습니다.
   - 예전 가장자리 좌표는 파일에서 지우거나 고쳐 쓰지 않고, 표시할 때만 잘리지 않는 범위로 조정합니다.
   - 기본 나무 간격을 넓히고, 새 배치에서는 나무·벤치의 바닥 공간을 고려합니다. 앞뒤로 다른 위치에 있는 가지가 자연스럽게 겹치는 것은 허용합니다.
   - 낮/밤 성장 크기, 돌봄에 따른 성장률, 이름·기념일·추억과 공개 정원의 기존 정수 성장 형식은 유지합니다.

## 적용 순서

1. 작업 중인 최신 프로젝트를 별도로 보관합니다. 로그인 서버의 실시간 환경변수·시크릿 연결·customAudiences·실행 계정·권한은 소스 ZIP만으로 복원되지 않습니다.
2. 1.0.26+29를 기준으로 작은 Update ZIP의 같은 경로 파일을 병합하거나, Full Source ZIP을 검토용 작업 폴더에 풉니다. 기존 Android 서명키, key.properties, Firebase 설정, 개인 서버 설정을 지우는 전체 폴더 삭제 방식은 쓰지 않습니다.
3. 서버의 실제 코드 변경은 `backend/garden-events.js`입니다. 운영 중인 gardenApi의 원본과 설정을 먼저 확인한 뒤 이 수정만 반영하여 배포합니다. socialAuth·verifyPlayPurchase·playNotifications 등을 일괄 재배포하지 않습니다. 운영 서버 소스가 다른 경우 무조건 덮어쓰지 말고 차이를 확인합니다.
4. 기존 서명키가 있는 Flutter 환경에서 `flutter pub get`, 테스트 후 `bash tool/build_mindnyang_play_bundle.sh`로 AAB를 빌드합니다. 이 스크립트는 기존 로그인/정원 URL과 Play Integrity 경로를 유지합니다. Android SDK와 기존 서명키는 별도 필요합니다.
5. Play 내부 테스트에 30 (1.0.27)을 올리고 기존 앱을 삭제하지 않은 채 업데이트합니다. 명상 기록 이전을 확인하려면 기존 기록을 유지해야 합니다.

이번 작업에서는 운영 서버 배포, 서명 AAB/APK 생성, Play 업로드를 수행하지 않았습니다. 디버그 App Check 토큰을 새로 요구하는 설정으로 바꾸지 않았습니다.

## 검증

- Flutter 전체 테스트: 575개 통과.
- Node 서버 전체 테스트: 167개 통과.
- Flutter 정적 분석: 오류 0개. 기존 경고는 별도 검증 결과 JSON에 수록합니다.
- 실제 파일 쓰기 실패, 평문 제거 실패, 명상 코스 저장 실패 후 저장소 닫기/재생성, 보상 저장 후 응답 실패, 공지 응답 유실 후 다시 열기/수정, 동시 공지 요청/삭제 후 재전송을 테스트했습니다.
- 360/390px에서 과거 가장자리 배치의 성숙한 나무 경계와 고정 뿌리를 검사했습니다. 정원 위젯의 실제 그림을 Flutter 테스트 환경에서 렌더링해 확인했습니다. 실기기 APK 화면 검증은 아닙니다.
- 원본과의 파일 해시 비교로 로그인 서버, 구독 서버, 영상 자산과 이번 수정 범위 밖 파일을 보존한 것을 확인합니다.

- 업데이트 후 기존 감정 응답·주간 돌아보기·백업 복원이 유지되는지.
- 아침/저녁 알림 켜기·시간 변경·끄기, 권한 거부 후 상태 표시.
