## 적용 기준과 결과

2026-10-16에 첨부된 최신 ZIP을 실제로 열고 원본의 파일 해시를 보관한 뒤 수정했습니다. 원본에는 `account_screen.dart`, `social_auth_service.dart`, `account_identity_policy.dart`와 서버 소셜 로그인 모듈이 없었습니다. 마이에는 로그인 진입이 없었고 이메일 계정 화면은 백업 화면 내부 및 서버 설정 조건 뒤에 있었습니다.

## 원본에서 발견한 테스트 4건

원본 ZIP을 별도 경로에 다시 추출하고 해당 3개 테스트 파일을 실제 실행해 **9 통과·4 실패**로 동일 문제를 재현했습니다. 이를 해결하기 위해 앱 동작을 바꾸지 않았습니다.

- `living_garden_scene_test.dart`: 고정된 몽이 이름 대신 사용자 지정 이름과 조사를 검증하도록 수정. 바람 기본 정지·사용자 재생·정지와 독립적인 눈 깜빡임·생명주기를 각각 확인합니다.
- `gentle_care_and_cards_test.dart`: 이미 삭제된 `dreamy` ID 대신 현재 37마리의 1,369개 조합에서 비진단 안내와 이용자의 선택권을 확인합니다.
- `garden_revision_test.dart`: 반복 애니메이션에 끝없이 기다리는 테스트 방식을 수정하고 방문자의 편집·개인 기억 접근 차단 검증을 유지했습니다.

이후 해당 테스트 13건과 전체 Flutter 테스트를 다시 실행해 모두 통과했습니다. 기존 명시적 skip 1건은 그대로 남아 있습니다.

## 계정과 데이터 처리

- 로그인은 로컬 편지·정원 저장 영역을 교체하거나 기록을 자동으로 다른 계정에 옮기지 않습니다.
- 서버는 Firebase가 검증한 Google 제공자 또는 서버가 검증한 카카오·네이버·페이스북 claim을 확인합니다. 화면에서 넘긴 이메일·닉네임으로 신원을 인정하지 않습니다.
- 제공사 키가 없거나 서버가 준비되지 않은 경우 성공으로 표시하지 않습니다. 메뉴는 계속 보이고 연결 준비 안내를 제공합니다.
- 서버 공개 상태는 현재 UID로 조회합니다. 다른 계정의 과거 공개 여부나 늦게 도착한 응답을 적용하지 않습니다. 조회 실패는 미확인 상태입니다.
- 탈퇴 시 이메일 미인증 사용자도 최근 로그인한 비익명 본인 계정이면 삭제를 요청할 수 있습니다. 소셜 재가입은 데이터 정리와 Auth 삭제가 확인된 경우에만 새 UID를 발급합니다.

## 아직 수행하지 않은 운영 확인

1. 구글·카카오·네이버·Meta 콘솔의 실제 키·리디렉션·검수 설정.
2. 운영 Firebase에 `socialAuth`와 수정된 `gardenApi` 배포, App Check 및 Custom Token 서명 권한 확인.
3. 실제 Android APK/AAB 컴파일과 서명. 첨부 ZIP에는 `android/key.properties`와 `android/release-key.jks`가 없었습니다. 원래 빌드 환경의 키를 보존해 사용해야 합니다.
4. 실제 계정 로그인·취소·재실행 유지·로그아웃·탈퇴, 두 휴대폰 사이의 공개 정원과 응원 송수신.
5. Play 결제와 기존 구매 복원. 이번 수정은 아이템 결제 서버를 새로 구축하거나 iOS/웹 소셜 로그인을 완성한 작업이 아닙니다.

실제 설정 절차는 `SOCIAL_LOGIN_SETUP_KO.md`와 `../backend/social-auth-setup.md`를 사용하세요. 소스 버전은 `1.0.9+12`이며, 실제 출시 빌드 번호는 Play Console의 마지막 번호보다 높아야 합니다.

## 보존 및 적용

실제 Firebase 설정·패키지명·원본 자산은 보존했습니다. 별도 패치에는 서명키·실제 Firebase 설정·제공사 비밀키를 넣지 않았습니다. 원본과 다른 추가 수정이 있는 프로젝트에는 `apply_patch.py --check`가 충돌을 표시하고 덮어쓰지 않습니다. 패치 적용 전 검사·적용·재적용 및 충돌 거부 동작을 별도로 확인합니다.
