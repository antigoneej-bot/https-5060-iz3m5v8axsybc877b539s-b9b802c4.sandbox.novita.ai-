이웃 정원 무작위 방문 — 내부 테스트 1.0.62 (65)

보존
- baseline/aab-64 브랜치: 기존 검증된 1.0.61 (64) 소스.
- feature/public-garden-discovery 브랜치: 이번 변경.
- 기존 AAB 64, 원본 수정본, 서명키, 사용자 기록, 구독/프리미엄 테스트 설정을 보존한다.
- 새 기능은 개인 기록·편지·백업 형식이나 로컬 저장소 스키마를 변경하지 않는다.

진입 및 화면
- 냥이 마을의 기본 버튼: 이웃 정원 둘러보기. 친구 코드는 보조 버튼으로 유지한다.
- 무작위 방문은 공개·삭제·Auth 계정 존재·양방향 차단을 다시 확인한 정원 1곳을 보여준다.
- 다른 정원으로 / 응원꽃 / 즐겨찾기 / 전체 보기 / 가로·세로 전환을 제공한다.
- 기존 목록 둘러보기, 초대 코드, 이웃 신청/수락, 고양이 초대, 꽃 선물은 유지한다.
- 방문과 즐겨찾기는 친구 연결, 공동 기억의 나무 참여, 기록 공유를 만들지 않는다.
- 기존 큐레이션 응원만 재사용한다. 자유 채팅이나 새로운 메시지는 추가하지 않는다.

동의와 접근
- randomVisitOptIn은 기존 discoveryOptIn과 별개의 새 선택이며, 기존 계정은 기본 false이다.
- 새 동의는 기존 커뮤니티 약관을 통과한 소유자 요청에서만 저장한다.
- 공개 범위가 public이고 discoveryOptIn 및 randomVisitOptIn이 모두 true일 때만 추천한다.
- 기존 앱에서 공개 범위/목록 동의를 철회해도 새 무작위 동의와 색인이 함께 해제된다.
- 공개 해제, 삭제/삭제 중 계정, Auth에 없는/비활성 계정, 자기 자신, 어느 방향이든 차단한 상대는 제외한다.
- 즐겨찾기는 방문 권한이 아니다. 목록과 재방문은 현재 공개/동의/차단/계정 상태를 다시 검사한다.
- 접근할 수 없는 즐겨찾기는 정원 이름/모습 대신 비공개 안내와 자기 즐겨찾기 해제 기능만 보여준다.
- 방문 중에는 15초 간격 및 앱 복귀 때 재확인하고, 확인 실패 또는 공개 해제 시 기존 화면을 숨긴다.
- 모든 전송·즐겨찾기 변경은 서버에서 접근을 재검사한다. 이미 전달된 공개 화면을 원격으로 회수할 수 있다고 주장하지 않는다.

공개 DTO
- 허용: 공개용 닉네임, 정원 식별자, 씨앗 성장/장식/배치, 기억의 나무 외형 단계,
  응원꽃/한정된 반응, 사용자가 선택한 고양이의 coat/stage, 방문자 자신의 즐겨찾기/이웃 상태.
- 제외: 이메일, 감정 기록, 편지, 개인 기억의 나무 날짜·내용, 고양이의 사적 이름, 초대 코드,
  비공개 공유 나무/노트, 알 수 없는 중첩 필드.
- 배치·장식·씨앗·고양이·반응은 서버에서 허용 목록과 범위를 검사한다.
- 기존 공동 기억의 나무 내용은 기존의 별도 초대/참여 권한 화면에서만 접근한다.
- Firestore 클라이언트 직접 읽기/쓰기는 기존 deny-all 규칙을 유지한다. Admin SDK 경로의 권한 검증은 API가 담당한다.

서버 자료 구조 및 비용
- gardenDiscovery/{uid}: rank, version 두 필드만 저장하는 서버 전용 색인.
- users/{viewer}/settings/discoveryHistory: 최근 8곳. 다른 사용자에게 노출하지 않는다.
- users/{viewer}/favoriteGardens/{target}: createdAt만 저장, 최대 200곳. 공개 스냅샷을 복제하지 않는다.
- 무작위 pivot으로 rank 범위와 wrap-around를 합쳐 최대 24개 색인 문서만 읽고 셔플한다.
- 현재 권한을 point read로 검사한다. 전체 users/villageProfiles 컬렉션을 스캔하지 않는다.
- 최근 방문을 우선 피하고, 작은 후보군을 모두 본 경우 가장 오래된 정원을 다시 허용하되 바로 직전 정원은 반복하지 않는다.
- 후보 창이 전부 숨김/차단/최근 방문이면 빈 상태와 재시도를 제공한다. 전체 데이터베이스에 정원이 없다고 단정하지 않는다.
- rank 단일 필드 범위/정렬 색인을 사용한다. 신규 복합 인덱스나 기존 인덱스 삭제는 필요하지 않다.
- 기존 API의 검증된 Auth/App Check, 계정 작업 잠금, 사용자별 20회/분 제한을 그대로 적용한다.
- 기존 응원 로그의 수신자/종류/일별 멱등성과 트랜잭션을 그대로 사용한다.

API 추가
- randomPublicGarden
- getPublicVisitGarden
- setFavoriteGarden
- listFavoriteGardens
- getVillageProfile 응답에 randomVisitsSupported=true를 추가한다. 구버전 서버는 기존 공개/친구 코드 기능으로 계속 동작한다.
- publishGarden/updateVillageProfile에서 randomVisitOptIn을 받으며, 공개 스냅샷에 publicCat(coat/stage)을 선택적으로 받는다.

배포
- 운영에서 사용하려면 gardenApi 소스 업데이트가 필요하다. 이번 소스/AAB 준비는 운영 배포를 뜻하지 않는다.
- 새 인덱스 컬렉션은 사용자가 명시적으로 동의·저장할 때만 채운다. 기존 계정의 동의나 데이터를 일괄 변경하지 않는다.
- Firestore/Storage 규칙, 기존 복합 인덱스, IAM, 비밀값, 나머지 함수의 설정 변경은 필요하지 않다.
- 배포 전 현재 gardenApi 소스/설정을 별도 백업하고 source-only field mask로 업데이트해야 한다.
- 되돌릴 때는 보존된 서버 소스와 설정을 사용한다. 사용자 기록이나 기존 Storage 파일을 지우지 않는다.
- 앱을 되돌려야 하면 앱 삭제 없이 보존한 64 소스를 더 높은 versionCode로 같은 키로 다시 빌드한다. 낮은 버전 강제 설치나 새 키 생성을 사용하지 않는다.
- 정식 출시 및 프리미엄 테스트 모드 해제는 이번 범위가 아니다.

검증 범위
- 백엔드 함수 단위 테스트, 실제 gardenApi 요청 처리기 테스트, 로컬 demo Firestore 에뮬레이터,
  Flutter 위젯/서비스/전체 회귀, 세로·가로 작은 화면의 조작 버튼 위치를 검사한다.
- 에뮬레이터는 127.0.0.1의 demo-mindnyang-discovery 프로젝트만 사용하며 운영 데이터를 사용하지 않는다.
- 최종 실행 결과와 AAB 서명/구조/버전 증거는 별도 출력 보고서에 기록한다.
- 운영 배포·Play 업로드·실기기 App Check/클라우드 백업·복원 검증이 완료된 것으로 표시하지 않는다.
