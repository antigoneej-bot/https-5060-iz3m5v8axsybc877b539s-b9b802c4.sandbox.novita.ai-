# 정원소식 날짜·회차 예약 (2026-10-21)

## 이번에 연결한 동작

- 운영자가 정원소식의 종류를 이벤트로 선택하면 온라인/오프라인, 장소, 비용 안내, 날짜·회차별 시작/종료, 신청 시작/마감과 정원을 입력할 수 있다.
- 한 소식당 최대 12회차, 회차 정원 1~1,000명. 사용자는 한 소식에서 한 회차를 직접 골라 신청한다. 다른 회차로 바꾸려면 기존 신청을 취소하고 다시 신청한다.
- 화면 시간은 기기의 현지 시간으로 표시하고 서버에는 UTC 시각으로 저장한다. 마감·정원 판정은 서버 시각과 실제 예약 수를 사용한다.
- 신청/취소는 Firestore 트랜잭션이다. 마지막 자리 동시 신청, 응답 유실 후 같은 요청 재시도, 중복 취소에서 좌석을 두 번 사용하거나 빼지 않는다. 계정 삭제 시에도 해당 회차의 자리만 반환한다.
- 운영자는 실제 신청자 목록에서 회차 날짜와 선택적으로 적은 이름·요청 사항, 계정에서 검증된 이메일을 본다. 편지·감정·돌봄 기록은 예약 데이터로 전달하지 않는다.
- 온라인 접속 링크는 일반 소식 목록/상세 응답에서 제외한다. 운영자 또는 신청한 본인에게만 별도 API로 제공하며, 취소된 회차는 접근을 막는다.
- 예약자가 있는 회차의 날짜 변경/삭제 및 현재 예약 수보다 작은 정원 설정을 막는다. 마감/회차 취소는 명시적으로 선택할 수 있으며 기존 신청 내역이 임의로 사라지지 않는다.
- 기존 날짜 없는 공지/예약도 그대로 조회·신청·취소할 수 있다. 구버전 운영자 클라이언트가 회차 필드를 생략해 수정해도 회차와 접속 링크는 보존한다.

## 운영자 초안

새 정원소식 편집기의 **함께 편지 쓰는 저녁 · 초안 불러오기**는 편집기에만 제목과 안내를 채운다. 운영자가 실제 날짜·회차·장소/접속 링크·비용을 확인하고 작성하기를 눌러야 공개된다. 자동으로 이벤트를 생성하거나 가짜 신청자 수를 채우지 않는다.

초안은 20분 동안 함께 기록하는 모임이며 카메라/편지 내용 공유가 선택임을 안내한다. 개인 상담 또는 치료를 제공한다고 표시하지 않는다.

## 배포와 실제 운영에서 남은 확인

- 이 소스 작업은 운영 서버 배포나 Play Console 업로드를 하지 않았다. `backend/garden-events.js`, 변경된 `index.js` 및 `account-reservations.js`를 포함한 백엔드 업데이트와 앱 업데이트가 필요하다.
- 기존 인증/App Check/운영자 역할 검사를 그대로 사용한다. `garden_news_admin`을 서버에서 검증하며 화면 버튼 노출은 권한 검사의 대체 수단이 아니다.
- 실제 두 계정으로 회차 선택 → 신청 → 다른 계정의 정원 갱신 → 운영자 목록 → 취소 → 자리 반환을 확인한다. 모임 링크는 신청하지 않은 계정에 노출되지 않아야 한다.
- 유료 모임의 비용은 안내 문구다. 이 기능이 클래스 결제를 대신 처리하거나 구독자 무료/할인 혜택을 자동 부여하지 않는다. 운영자가 실제 혜택과 별도 결제 방법을 명확히 공지해야 한다.
- 회차 취소/변경을 위한 자동 푸시, 출석 처리, 정기 반복 일정, 대기열은 이번 범위에 추가하지 않았다. 운영자는 실제 공지와 기존 연락 절차를 사용한다.
- 신청 데이터에는 선택적 이름·메모와 검증된 이메일이 포함될 수 있으므로 실제 운영 개인정보 안내에 보관 기간/이용 목적을 일치시킨다. 삭제 시 공지의 예약 문서도 정리한다.

## 1.0.22 보완: 신청 결과와 취소 경로 유지

- 신청 API가 돌려준 확인 내역을 즉시 사용한다. 신청 성공 후 별도 조회가 끊겼다는 이유로 신청 실패로 표시하거나 같은 좌석을 다시 신청하게 하지 않는다. 구서버가 `reserved: true`만 돌려주는 경우에도 확인된 신청 상태는 유지한다.
- 날짜 없는 기존 모임에 신청자가 있으면 예약 기능 삭제와 신청 인원 아래로 정원 축소를 서버와 편집기에서 막는다. 이미 예전 편집으로 정원이 없어진 소식도 내 신청 내역과 취소 버튼이 보인다.
- 정원소식 상단 **내 신청 내역**에서 본인의 실제 신청 날짜·회차·취소 상태를 확인하고 모임 상세로 들어가거나 신청을 취소할 수 있다. 계정이 바뀌면 다른 계정의 신청 내용은 지우고 화면을 다시 열도록 안내한다.
- 소식 삭제가 신청자 정리 중 끊기면 운영자 목록에 **삭제 마무리하기**가 남는다. 일반 이용자 목록과 모임 접속 링크에서는 숨겨지며 새 신청은 막는다. 재시도는 이미 정리한 문서를 다시 만들지 않는다.
- 홈/소식 캐시는 운영자 전용 접속 링크와 삭제 정리 항목을 보관하지 않으며 계정이 바뀌면 캐시를 재사용하지 않는다.
- 추가 검증 범위: 예약 확인 직후 네트워크 단절, 계정 변경 중 응답, 기존 예약 기능 제거 방지, 삭제 도중 실제 저장소 오류 주입과 관리자 재시도, 내 신청 목록의 날짜·취소 동작. 운영 서버의 실제 기기간 확인과 클래스 일정 푸시 알림은 별도이다.
