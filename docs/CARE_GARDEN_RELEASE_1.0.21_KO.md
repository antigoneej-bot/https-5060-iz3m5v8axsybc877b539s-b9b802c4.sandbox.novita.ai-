# 마음냥 정원 1.0.21+24 — 편지 이후의 돌봄과 연결

이 변경은 저장된 1.0.20+23 소스를 기준으로 합니다. 기존 카카오 로그인, Play Integrity, 구매 소유자 확인, 구독 알림 수신 수정과 알림 권한 수정을 포함합니다. 실제 운영 중인 소스와 기준 파일이 다르면 전체 덮어쓰기 대신 차이를 확인해야 합니다.

## 사용자가 만나게 되는 흐름

1. 편지를 저장하면 자동 답장 대신 고양이와 조용히 마무리합니다. 선택적으로 지금의 느낌, 원문에서 직접 고른 문장, 자신에게 남길 말을 기록합니다. 아무것도 추가하지 않고 정원으로 가도 됩니다.
2. 홈의 **나를 돌보는 방법**에서 작은 행동을 계획하고, 실제로 해본 뒤 완료와 도움 여부를 표시합니다. 계획을 실천으로 자동 계산하지 않습니다. 받은 응원은 본인이 선택했을 때만 돌봄 모음에 담습니다.
3. 홈이나 정원 메뉴의 **정원 기록집**에서 달을 고르고 편지의 문장, 기념 나무, 도움이 됐다고 표시한 실천을 선택합니다. 정원 배치에는 실제 보관한 시각이 표시됩니다. 나중의 생각은 원문을 덮어쓰지 않고 날짜를 붙여 추가합니다.
4. **냥이 마을 → 함께 가꾸는 기념 나무**에서 수락한 이웃을 초대합니다. 상대가 수락하면 실제 서버에 물주기와 공동 메모를 저장합니다. 개인 편지와 감정 통계는 나무로 전송하지 않습니다.
5. **정원 소식 → 운영자 작성**에서 날짜와 시간, 일정별 정원, 신청 기간, 장소 또는 온라인 모임 정보를 입력합니다. 함께 편지를 쓰는 모임의 초안 양식도 제공하지만 자동으로 게시하지는 않습니다.

## 무료와 구독

| 기능 | 이용 범위 |
| --- | --- |
| 편지 작성, 마무리, 기본 돌봄 기록 | 무료 |
| 기본 이웃 응원과 기존 선물 전달 | 기존 정책 유지 |
| 첫 기본 정원 기록집 | 무료 |
| 새로운 달의 기록집, 새 계절 표지, 여러 달 비교 | 기존 마음냥 구독 |
| 공동 기념 나무 만들기·새 스타일 선택 | 만든 사람의 구독 확인 |
| 초대 수락·기존 공동 나무 돌보기·메모 | 초대받은 친구 무료, 구독 종료 후 기본 참여 유지 |
| 이미 저장한 기록집 읽기·편집·나중의 생각·공유 | 구독 종료 후에도 가능 |
| 클래스·오프라인 모임 | 공지의 참가비와 조건 적용. 무제한 무료 혜택을 약속하지 않음 |

상품 ID, 가격, 결제 계정 연결 방식은 변경하지 않았습니다. 기존에 저장한 고양이 답장은 읽을 수 있지만 새 답장이나 답장 도착 알림은 만들지 않습니다. 방문·스트릭 알림은 유지합니다.

## 기록 보관과 삭제

- 돌봄과 기록집은 기기의 암호화 저장소 및 기존 암호화 백업에 포함합니다. 다른 로그인 계정으로 바꾸어도 한 기기의 개인 정원이라는 기존 정책을 유지합니다.
- 공유는 사용자가 미리보기에서 고른 항목만 내보냅니다. 개인 문장은 처음부터 공유 항목으로 선택되어 있지 않습니다.
- 원본 편지·돌봄 실천·식물 기억을 삭제하면 기록집의 해당 복사본도 제거합니다. 열린 편집창이 삭제된 원본을 다시 저장하지 못하도록 원본을 다시 확인하고 저장·삭제를 직렬화합니다.
- 이전 백업이나 이미 외부로 공유한 파일은 원본 삭제로 자동 삭제되지 않습니다.
- 공동 나무의 변화는 화면 재진입, 새로고침, 앱 복귀 시 갱신합니다. 실시간 푸시 동기화가 아닙니다.
- 공동 나무 참여 계정 삭제 시 해당 공동 나무와 메모, 양쪽 인덱스를 삭제합니다. 단순 나가기는 별도 동작이며 화면에서 안내합니다.
- 사용 통계 공유는 기본 꺼짐을 유지합니다. 새 계측은 생성·열람·완료·공유 같은 기능 이벤트만 사용하며 문장, 감정, 친구 코드, 공동 메모를 넣지 않습니다.

## 적용 순서

1. 현재 작업 디렉터리와 서명키를 안전하게 보관합니다. 업데이트 ZIP은 `android/key.properties`, `*.jks`, Firebase 설정, 패키지명, 기존 영상 자산을 교체하지 않습니다.
2. 업데이트 ZIP의 `apply_update.py`를 먼저 `--check`로 실행합니다. 기준과 다른 파일은 자동 덮어쓰지 않습니다. 충돌이 있으면 해당 파일의 수정사항을 함께 검토합니다.
3. 검사가 통과하면 같은 도구의 `--apply`로 파일을 적용합니다. 변경 전 파일은 별도 백업 폴더에 보관합니다.
4. `flutter pub get`과 필요한 테스트를 실행합니다. 운영 환경에 배포된 `gardenApi`의 소스·환경 변수·실행 계정·App Check 설정을 확인한 뒤 새 `backend/garden-events.js`, `backend/shared-trees.js` 및 관련 API 변경을 배포합니다.
5. 앱에서 쓰는 기존 서버 주소를 유지합니다. `socialAuth`, `playNotifications`, Firestore 규칙, 서비스 계정·IAM을 이유 없이 다시 만들거나 삭제하지 않습니다. `backend/package.json`에는 기존 RTDN 코드에서 사용하는 Functions Framework의 직접 의존성이 추가되어 있습니다.
6. 기존 서명키가 있는 빌드 환경에서 `bash tool/build_mindnyang_play_bundle.sh`를 실행해 AAB를 만듭니다. 기존 Play 앱의 내부 테스트 트랙으로 **버전 코드 24**를 올립니다. 이미 더 높은 버전 코드를 사용 중이라면 그보다 높게 올려야 합니다.
7. 테스터는 Play 내부 테스트 링크에서 업데이트합니다. 개발용 App Check 디버그 토큰을 각 휴대전화에 다시 등록하는 배포 방식으로 바꾸지 않습니다.

## 실제 기기로 확인할 항목

- 기존 카카오 로그인 세션과 구독 복원 유지, 결제 취소·갱신 후 권한 반영.
- 일반 편지와 마음 편지 저장 → 마무리 건너뛰기/선택 저장 → 정원 성장 유지.
- 돌봄 계획 → 실제 완료 → 도움 여부 → 돌봄 모음/기록집 반영.
- 원본 삭제 후 기록집에서 문장이 제거되는지, 백업·복원 후 새 기록이 유지되는지.
- 구독자 A가 무료 이웃 B를 초대 → B 수락 → 서로 물주기와 메모 확인 → 차단·나가기 후 접근 제한.
- 실제 공개한 테스트 모임의 날짜 선택 → 정원 초과 방지 → 신청 취소 → 자리 회복.
- 구독 종료 후 기존 기록집 읽기·수정·공유, 기존 공동 나무 참여 유지.

이번 작업은 소스 구현과 로컬 검증입니다. 운영 서버 배포, Play 업로드, 서명된 Android 빌드와 두 실제 휴대전화 간 검증은 수행 완료로 표시하지 않습니다. 검증 결과의 정확한 실행 수치는 함께 제공한 `RELEASE_VERIFICATION.md`를 참고하세요.
