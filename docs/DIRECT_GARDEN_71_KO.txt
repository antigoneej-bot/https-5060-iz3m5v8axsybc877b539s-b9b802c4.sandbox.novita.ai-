기존 정원의 조작성 개선 / 기준 1.0.67+70 / 변경 1.0.68+71

보존 기준: 01ffe9c (식물 그림 선택창 70).
feature/direct-garden-planting-71 브랜치에서 작업합니다.
이전 무작위 이웃 탐색 페이지 보완 및 실행 스크립트 LF 수정은 보존합니다.

1. 실제 정원 직접 진입
정원 탭에 GardenWorldScreen(cultivation:true,embedded:true)를 직접 표시합니다.
기존 GardenWorldView와 StorybookBackdrop/Foreground/Atmosphere, 기존 식물/장식 좌표를 사용합니다.
홈·마음돌보기·모든 기능의 시안과 하단 내비게이션은 유지합니다.
정원 안 좌우 이동과 탭 넘김이 충돌하지 않도록 정원 탭에서는 페이지 스와이프를 끕니다.

2. 조작
하단 씨앗 심기/물주기/내 식물/전체보기를 고정합니다. 작은 폭/큰 글자는 2행으로 바꿉니다.
씨앗 개수는 상단에 표시합니다. 정원은 별도 Expanded 영역으로 확보해 도구가 덮지 않습니다.
기억의 나무/열매 정원/이웃 정원/장식/기존 배치·확장 도구/전체화면은 보조 메뉴에 남깁니다.

3. 심기
씨앗 선택창 -> 기존 정원의 잔디 위치 선택 -> 여기에 심기 확인.
보조 메뉴에 남긴 기존 배치 도구에서 심기를 시작해도 동일한 위치 선택/확인 흐름으로 전환합니다.
선택 중 허용된 기존 지면 범위를 표시하고 반투명 새싹을 보여줍니다.
위치 검사는 기존 GardenLayout.onGround/placementError와 종류당 한 개 구조를 재사용합니다.
잠긴 구역, 겹침, 정원 범위 밖은 확인할 수 없습니다. 취소는 저장하지 않습니다.
선택 시작 시 중앙 잔디를 보여주며, 기존 식물을 찾을 때는 원래 저장 좌표로 이동합니다.

4. 저장 일관성
MongiGardenStore.plantAt에서 최신 씨앗/식물/장식/좌표를 다시 읽고 검사합니다.
기존 LocalRecordTransaction 및 각 저장소 큐로 심기·배치·다른 기록 쓰기를 직렬화합니다.
기존 SessionTransaction의 durable pending journal에 최종 garden 값과 선택적 layout 값을 함께 기록합니다.
저널 복구는 증가 연산이 아니라 최종 값을 다시 씁니다. 씨앗 수가 반복 감소하지 않습니다.
기존 StorageService.init의 SessionTransaction.initialize가 재시작 복구를 수행합니다.
완료한 종류와 같은 좌표의 재시도는 멱등 처리합니다. 다른 좌표의 기존 종류는 재심기하지 않습니다.
중간 쓰기 실패는 저널을 남기며, 복구 전 새 쓰기가 그 결과를 덮지 않게 합니다.
저널 전 실패는 변경 없음, 저널 후 실패는 복구 시 두 저장소의 커밋을 완료하는 방식입니다.
지속적인 디스크 고장 자체를 복구하거나 구버전이 미완료 신규 저널을 처리한다고 주장하지 않습니다.

5. 식물 찾기·성장
저장한 식물부터 카메라를 시작하며, 심기/목록 위치 보기 후 해당 식물을 3초 강조합니다.
선택창은 심을 수 있는 씨앗과 이미 심은 식물을 구분합니다.
미심은 식물은 다 자란 모습 미리보기, 심은 식물은 실제 저장된 성장 그림을 표시합니다.
내 식물은 이름/현재 성장/오늘 물주기 상태와 위치 보기/물주기/추억 기록을 제공합니다.
물주기 일일 제한, 성장 수치/분수 돌봄, 구역 해금, 장식 이동, 동반 고양이 심기/물주기 추억을 재사용합니다.

6. 범위·배포·검증 한계
서버/인증/구독/IAM/규칙/인덱스/상품은 수정하거나 배포하지 않습니다.
화면 캡처는 분리된 테스트 데이터의 실제 Flutter 실행 화면입니다. 실제 휴대폰 기록을 읽은 것이 아닙니다.
기존 사용자 데이터 형태를 가진 테스트와 저장소 재열기/실패 주입으로 보존을 검사합니다.
연결된 ADB 기기가 없어 휴대폰의 설치 버전·기존 기록·App Check·결제·실기기 성능은 미검증입니다.
확인된 이전 코드 70보다 높은 71로 빌드합니다. 다른 환경에서 71 이상을 설치했다면 더 높은 코드가 필요합니다.
APK의 기존 로컬 업로드 키와 Play의 앱 서명 키는 다를 수 있습니다. 서명 불일치 시 앱 삭제로 해결하지 않습니다.
실제 테스트 로그와 최종 APK/AAB 서명 검증 결과는 전달 보고서에 별도로 기록합니다.

복구/보존
기존 70 소스·APK 이전 산출물은 덮어쓰지 않습니다. 최초 심기 데이터와 좌표의 저장 형식은 기존 버전을 유지합니다.
되돌려야 할 경우 현재 버전에서 미완료 저널 복구를 완료하고 백업을 확인한 뒤,
보존한 70 소스에 기존 키와 더 높은 버전 코드를 사용해 업데이트해야 합니다.
개인 기록이 있는 설치본을 삭제하거나 낮은 버전을 강제로 덮는 방식은 사용하지 않습니다.
