# 마음냥 정원 전체 소스 재검토

검토일: 2026-10-16 / 기준 소스: 1.0.13+16 / 보완 소스: 1.0.14+17

**판정: 안드로이드 기준 기능 완성도 82/100. 판매할 만한 매력은 있지만, 지속 구독을 만들었다는 증거는 아직 없다.**

이 점수는 소스 구현·예외 처리·연결 완성도를 검토한 판단이다. 사용자 만족도 조사, 임상 효과, 매출 성공 확률을 나타내지 않는다. 전체 ZIP과 작업 소스의 일치를 확인한 뒤 Dart 파일 355개의 구조 및 주요 진입·저장·서버·결제 경로를 나눠 추적했다. 모든 화면을 실제 폰에서 장기간 사용한 검증은 아니다. 이미 운영 중인 서버가 어느 소스 버전인지도 이번 검토로 확인하지 않았다.

## 2. 이번에 실제 보완한 내용

1. **활동 점수를 심리 상태로 해석하던 오류**: 출석·편지·돌봄으로 쌓이는 값이며 보상 때 100에서 0으로 돌아가는데, 기존 화면은 긍정·부정·회복·지침으로 해석했다. 이를 ‘돌봄 온기 기록’과 숫자 구간으로 바꿨다. 실제 선택 감정 통계와 보상 계산은 유지했다.
2. **서버 지연이 내 정원 표시를 막던 흐름**: 로컬 정원을 먼저 표시하고 받은 꽃은 뒤에서 동기화한다. 실패 시 정원을 계속 이용하면서 다시 확인할 수 있다. 계정 변경·화면 종료 뒤의 오래된 응답도 처리하지 않는다.
3. **앱 시작과 결제 초기화**: 첫 화면을 띄운 뒤 구독을 확인한다. 동시에 여러 화면이 초기화를 요청해도 같은 작업을 기다려 구매 스트림과 상품 조회가 중복되지 않게 했다.
4. **구독 확인 요청의 경합**: 계정의 다른 서버 작업 때문에 명시적으로 거절된 `account-busy`만 짧게 재시도한다. 결제를 새로 요청하거나 응답 유실을 임의로 재결제하지 않는다.
5. **명상 백업 누락**: 즐겨찾기·최근 명상·사후 응답·코스 진행을 정확한 키와 데이터 형태로 검증해 백업·복원한다. 인증·결제 권한·알림 허용 상태를 백업으로 복원하지 않는다. 설정만 복원했을 때 ‘0개 복원’으로 보이던 안내도 정리했다.
6. **알림 설정과 실제 예약의 불일치**: 방문·돌보기 알림을 켜면 권한 확인과 예약을 바로 수행한다. 거절·실패를 성공처럼 표시하지 않는다. 앱에 실제 복귀하면 방문 알림을 갱신한다. 신규 이용자는 기본 꺼짐이고 기존 선택은 유지한다.
7. **화면과 상품 안내 정합성**: 마이에서 냥이 마을로 직접 들어가도록 연결하고 정원 이야기·엽서에 사용자가 정한 고양이 이름을 적용했다. 실제 없는 광고 제거 혜택과 오래된 튜토리얼 안내를 정리했다. 선택한 Play 상품이 확인되지 않으면 구매를 막고 다시 확인할 수 있게 했다.

이번 보완은 앱·테스트·문서 변경이다. 새 광고나 아이템 결제, FCM 푸시, 새로운 가격제를 붙이지 않았다. 서버 코드는 직전 냥이 마을 버전에서 변경하지 않았다. 최종 자동 검증 수치는 함께 제공되는 검증 JSON과 로그에 기록한다.

## 3. 아직 남아 있는 중요한 부분

### A. 출시 확대 전에 먼저 해결할 기능 연결

**통계가 같은 사람의 기록을 일관되게 보여줘야 한다.**

`emotion_statistics_screen.dart`는 편지 기록을 사용하고, `mongi/screens/mind_report_screen.dart`는 별도 정원 일기를 사용한다. 편지를 써도 다른 리포트에서는 기록이 부족하다고 나올 수 있다. 먼저 화면에 출처를 명확히 표시하고 공통 기록 조회 계층을 만든다. 감정 종류·강도·활동 보상·명상 후 느낌은 서로 다른 값이므로 하나의 임의 점수로 합치지 않는다.

**명상 후 답변을 다시 보여줘야 한다.**

‘편안해짐/비슷함/불편함’은 저장하지만 이를 읽어 주간 회고나 다음 실천 선택에 보여주는 화면이 없다. 예를 들어 ‘지난 5회 중 3회에 편안해졌다고 남겼어요’는 본인의 응답을 돌려주는 설명이다. 이를 치료 효과나 원인으로 단정해서는 안 된다.

**오래된 선물과 이웃 목록의 조회를 확장해야 한다.**

- `backend/garden-village.js`의 받은 마음은 최근 80개·미확인 80개·처리 대기 30개를 조합하며 페이지네이션이 없다. 오래전에 확인한 꽃은 원래 기기나 별도 백업에 남아도, 새 기기에 로그인만 해서 모두 다시 가져오지는 못한다.
- 둘러보기는 공개 동의 문서 첫 80개를 가져온 뒤 섞는다. 그 밖의 정원은 노출되지 않는다. 커서·회전 조회 등으로 참여 정원이 늘어도 발견될 수 있게 해야 한다.
- 이웃 관계 목록도 조회 상한이 있으므로 무제한 이웃 기능으로 홍보하지 않는다.

**공개 정원은 자동 공유가 아니라 저장된 스냅샷이다.**

심기·물주기·배치 변경 후 설정에서 다시 저장해야 방문자에게 반영된다. ‘공개 정원 업데이트’ 버튼을 정원에서 쉽게 찾도록 하고, 저장하지 않은 변경 여부를 알려주는 방식이 우선이다. 개인 정원 역시 실시간 다기기 동기화가 아니라 백업·복원 방식이다.

### B. 지속성을 만드는 제품 과제

- **이웃 소식 알림:** 현재 로컬 리마인더와 별개로 이웃 신청·선물 도착 FCM 푸시는 없다. 우선 홈/정원 입구의 도착한 마음 표시, 이후 동의한 사용자에게 묶음 알림을 제공하는 순서를 권한다.
- **기념일 나무:** 이름·메모와 성장 기록은 있으나 별도 기념일 선택·100일 자동 기념·나무별 여러 추억 연혁은 없다. 친구·커플·가족의 기념 정원으로 판매하려면 이 부분이 필요하다.
- **장기 성장:** 씨앗은 6종이고 종류별 하나의 성장 값이 최종 단계에 도달한다. 여러 달 이후 어떤 기억과 변화가 쌓이는지 설계가 필요하다. 벌점이나 연속 출석 압박을 늘리는 방식은 이 앱의 목적과 맞지 않는다.
- **관찰 지표:** 편지·명상·구독·재방문 이벤트는 있지만 새 이웃 연결→방문→응원→재방문 흐름을 측정하는 계측은 부족하다. 동의한 이용자의 개인정보 없는 행동 지표로 확인해야 한다.

### C. 실제 수익 경로와 출시 범위

| 항목 | 현재 소스 상태 |
|---|---|
| Android 월·연 구독 | 구현됨. 실제 Play 상품·서버 검증·계정 복원 시험 필요 |
| 개별 아이템 유료 구매 | 구매 서비스가 비활성 스텁이며 실제 판매 화면 연결 없음 |
| 무료 이용자 광고 | 광고 위젯은 있지만 실제 화면 배치가 없어 현재 광고 매출 경로로 볼 수 없음 |
| 네 가지 간편 로그인 | Android 코드 존재. 공급자 콘솔·서명·서버 설정과 실기기 확인 필요 |
| iOS | Firebase·인증·스토어·서버 앱 허용 등 별도 작업 필요 |
| 기관용 대시보드 | 개인 통계와 별개인 조직 관리·집계·권한 시스템은 없음 |
| 상담·클래스 | 정원소식·예약 기반은 있으나 실제 제공 기관 계약·상품 운영이 완료됐다는 근거 없음 |

기본 소스 가격은 월 4,900원·연 29,000원이다. 실제 판매가는 스토어에서 확인한 조건을 따른다. 과거 논의한 55,000원 프리미엄과 무료 클래스가 이번 소스에 구현됐다고 보아서는 안 된다. 가격을 먼저 올리기보다 실제 제공되는 정원 장식·이야기·회고 혜택을 명확히 묶는 편이 좋다.

앱 자산 원본은 약 **261.6MB**이며, 고양이 영상 약 118.7MB·명상 음원 약 38.7MB·폰트 약 16.8MB가 포함된다. 이는 APK 다운로드·설치 크기와 다르다. 실제 AAB의 기기별 다운로드 크기를 측정하고, 영상·음원의 선택 다운로드와 필요한 폰트만 포함하는 방식을 검토한다.

## 4. 경쟁 앱과 판매 매력

| 비교 앱 | 공식적으로 제공하는 가치 | 마음냥이 집중할 부분 |
|---|---|---|
| Finch | 반려 캐릭터, 목표·기록·호흡, 친구 응원, 옷·가구 선물, 계절 콘텐츠 | 고양이·정원 취향과 개인의 기억이 장소에 쌓이는 경험. 응원·선물 기능 자체를 독창적이라고 주장하지 않기 |
| Daylio | 감정·활동 통계, 활동 유무에 따른 차이와 기록 패턴 | 읽기 쉬운 한국어 회고와 작은 실천으로의 연결. 기록 출처와 수치 의미를 일관되게 만들기 |
| 마보 | 명상 콘텐츠, 기업용 이용 관리, 챌린지·사전사후 보고서·현장 클래스 구성 | 일상에서 돌아오게 하는 정원과 부담 없는 이웃 경험. 기관 판매는 실제 운영·집계 기능을 갖춘 뒤 확장 |

Finch가 이미 무료 응원과 선물을 제공한다는 점은 경쟁이 있다는 증거다. 마음냥 수요나 성공을 보장하는 증거는 아니다. 세 앱이 제공하는 기능을 모두 늘리기보다 **“내 마음을 남기면 정원이 자라고, 이웃의 응원이 꽃으로 남는 곳”**이라는 한 경험을 분명하게 만드는 편이 낫다.

잘 맞을 법한 첫 고객은 고양이와 정원 꾸미기를 좋아하고, 긴 일기나 공개 게시글보다 짧은 기록과 조용한 교류를 선호하는 사람이다. 전문 상담을 바로 받으려는 사람, 경쟁 게임의 빠른 재미를 기대하는 사람, 세밀한 분석 도구만 원하는 사람에게는 현재 매력이 약할 수 있다. 이는 사용자 조사 전의 가설이다.

현재 앱에는 설치해 보고 싶은 소재가 있다. 장기 구독을 유지하려면 ‘이번 달에도 내 정원과 내 기억에 새 가치가 더해졌다’는 경험이 필요하다. 답장을 주력 유료 상품으로 강조하기보다 정원·기억·회고·연결을 전면에 두는 방향이 사용자가 밝힌 원래 목적과 맞는다.

## 5. 좋은 아이디어 세 가지

1. **이번 주 나를 도운 것**: 편지와 명상 후 응답에서 본인이 직접 남긴 사실을 묶어 보여주고, 다음 주 작은 실천 하나를 선택하게 한다. 기존 데이터를 활용하며 추가 입력 부담을 줄인다.
2. **우리의 기념 나무**: 기념 날짜와 이름을 정하고 한 나무에 여러 추억을 덧붙인다. 30일·100일에 개인 기록을 공개하지 않는 엽서를 만든다. 친구·커플뿐 아니라 ‘내가 다시 시작한 날’도 지원한다. 현재 공동 편집이나 기념일 자동화가 구현됐다는 뜻은 아니다.
3. **오랜만에 돌아온 정원**: 지난 방문 이후 받은 꽃·자란 나무·기억 한 장을 조용히 보여준다. 답례나 매일 출석을 강요하지 않는다. 먼저 오래된 선물 조회와 공개 정원 갱신을 안정화해야 한다.
